# Пайплайн: как получен актуальный набор иконок

Здесь закреплена **вся последовательность действий** — от 82 исходных листов до
набора, который лежит в `icons-256/`. Всё воспроизводимо: каждая строка это ровно
та команда, которая дала текущий результат, а проверить её можно `tools/verify_set.py`.

## Что где лежит сейчас

| папка | роль | что это | вес |
|---|---|---|---|
| `RPG Loot Icons 01…41` | источник | 82 листа JPG (41 пак × 2 части) | — |
| `cut_icons/` | промежуточное | 4100 палитровых PNG, вырезанных из листов | 4100 файлов |
| `icons-256-base/` | **база** | чистый набор 256×256 (enhance + Laplacian), **без стиля** — источник для стилизации | 44.7 МБ |
| **`icons-256/`** | **актуальный** | база + `quiet+vign`: 4100 WebP 256×256 | **39.1 МБ** |
| `icons-256-v2/` | кандидат | source-first: полноцветный кроп JPG → anti-ringing 256 → `quiet+flat+vign+fit+punch` → мягкое восстановление среднечастотных деталей | 47.2 МБ |
| `icons-512/` | предыдущий | 512×512, полный рост (до решения про 256) | 83.3 МБ |

`role` каждой папки записан в её `manifest.json` (`base` / `actual` / `candidate` /
`previous`),
поэтому наборы нельзя перепутать: у актуального есть блок `style` и поле
`derived_from`.

## Последовательность (6 шагов)

Одной командой: `tools/build_set.sh all` — она делает шаги 2–6 и проверки.
По шагам:

```bash
# 0. окружение
python3 -m venv .venv && .venv/bin/pip install -r tools/requirements.txt

# 1-2. вырезать иконки из листов (4100 PNG, минуты)
.venv/bin/python tools/cut_icons.py

# 3. собрать чистую базу 256×256 (WebP q92 + enhance + Laplacian, ~7 мин в два процесса)
#    (в README это изначально и называлось 'каноном icons-256')
.venv/bin/python tools/repack_icons.py --size 256 --quality 92 \
    --denoise 0.014 --steer 1.4 --sharpen 0.28 --sharpen-sigma 1.0 --laplacian 0.70 \
    --out icons-256-base

# 4. выпечь стиль поверх базы (4100 иконок, ~1 мин на 2 ядрах)
.venv/bin/python tools/stylize.py --set icons-256-base --apply quiet+vign --out-dir icons-256

# 5. (необязательно) старый набор 512 px
.venv/bin/python tools/repack_icons.py --out icons-512

# 6. проверки
tools/build_set.sh verify
```

Шаги 3 и 4 и есть «актуализация»: **база отдельно, стиль поверх неё отдельно**,
поэтому любой другой стиль можно примерить, не трогая базу:

```bash
.venv/bin/python tools/stylize.py --set icons-256-base --apply cel --out-dir /tmp/probe --limit 300
.venv/bin/python tools/stylize.py --set icons-256-base --apply quiet+vign --out-dir icons-256
```

## Что делает каждый шаг и что должно получиться

| шаг | команда | ожидаемый результат |
|---|---|---|
| 1 | `tools/cut_icons.py` | 4100 PNG, 82 листа по 50 иконок, режимы `frame` 78 / `grid` 4 |
| 2 | `tools/qa_icons.py cut_icons png` | `problems: none` |
| 3 | `tools/repack_icons.py --size 256 … --out icons-256-base` | 4100 WebP 256×256, манифест с `role: base`, `enhance.config` = параметры строки выше |
| 4 | `tools/stylize.py --set icons-256-base --apply quiet+vign --out-dir icons-256` | 4100 WebP 256×256, 39.1 МБ (на 12.4 % легче базы), манифест с `role: actual`, `style.presets: ["quiet","vign"]`, `derived_from: icons-256-base` |
| 5 | `tools/repack_icons.py --out icons-512` | 4100 WebP 512×512, 83.3 МБ, `role: previous` |
| 6 | `tools/verify_set.py icons-256` | 4100/4100 md5, размеры, байты — `problems: none` |

## Почему именно так: решения, которые привели к этому результату

1. **Канон — 256 px, а не 512.** Нативный кроп ≈148×149, поэтому 512 — это
   апскейл ×3.46 с мылом, а 256 — честный ×1.73 без видимых потерь; набор втрое
   легче (39–45 МБ против 83 МБ) при том же виде в Foundry.
2. **Потерянные иконки восстановлены.** Детектор рамок пропускал 4 иконки на
   4 листах из 82 (сдвинутый тайл + кайма под артом). Добавлен `refine_rect`:
   отклонённый прямоугольник получает один шанс притянуться к линии; остальные
   78 листов остались байт-в-байт прежними. Итог: 4100 иконок вместо 4096.
3. **Палитра 255 цветов отброшена.** `cut_icons/` терял >97 % градиентов
   (медиана 9339 цветов → 255), поэтому набор собирается полноцветным WebP
   (`repack_icons.py`), а `cut_icons/` остаётся только промежуточным шагом.
4. **Стилизация выделена в отдельный слой.** `imgproc.py` только чистит
   (JPEG-шум, звон ресемплера, лестница 148 px), `stylize.py` меняет сам вид.
   Пока это были одни и те же 256 px, сравнивать было не с чем.
5. **Найдена настоящая причина «разъезжающегося» набора.** Замеры лаборатории
   показали: не стиль рисунка, а **подложки** — у каждой иконки за предметом
   своё свечение/дым своей яркости (до +40 уровней из 255). 4100 иконок в гриде
   читались как 4100 разных картинок.
6. **Выбран `quiet+vign`.** Он приводит подложки к одному тёмному тону и даёт
   одинаковую виньетку: Δ от базы 8.2 уровня, а файлы становятся **на 12.4 %
   меньше** (44.7 → 39.1 МБ) — плоская подложка кодируется дешевле градиента.
   Остальные пресеты проверены и отклонены как «другая игра»: `palette`
   (квантование в 48 цветов) делает файлы на **38 % тяжелее**, `pixel` меняет
   размер арта, `glow`/`loot` поднимают фон на 3–5 уровней, `cel`/`paint`/`ink`
   меняют технику рисунка. Полные таблицы — `docs/style-lab/README.md`.
7. **База и актуальный набор разведены.** Стиль необратим, поэтому чистый набор
   сохранён как `icons-256-base/`: из него можно переиграть любой другой стиль,
   а `icons-256/` остаётся тем, что используется в игре.

## Проверки (что именно проверяется)

```bash
tools/build_set.sh verify          # всё сразу
.venv/bin/python tools/qa_icons.py icons-256 webp      # число иконок, размеры, дубликаты
.venv/bin/python tools/verify_set.py icons-256         # контракт манифеста
.venv/bin/python tools/verify_set.py icons-256 --json  # то же машинно-читаемо
```

`verify_set.py` сверяет по каждой иконке: файл существует, `bytes` и `md5`
совпадают с манифестом, размер из WebP-заголовка равен `size`, а также
`count`, `total_bytes`, отсутствие лишних файлов и дублей по md5 по всему набору.
Скрипт `build_set.sh verify` дополнительно проверяет, что актуальный набор
**действительно отличается** от базы (средняя |разница| > 3 уровней), — защита
от случайной выпечки «в ту же папку без изменений».

Текущее состояние (проверено перед коммитом):

```
icons-256-base  role=base      4100 files  44.7 MB  md5 4100/4100  problems: none
icons-256       role=actual    4100 files  39.1 MB  md5 4100/4100  problems: none
icons-256-v2    role=candidate 4100 files  47.2 MB  md5 4100/4100  problems: none
icons-512        role=previous  4100 files  83.3 MB  md5 skipped (4101-й файл — манифест)
```

### Source-first merge в `icons-256-v2`

Кандидат `icons-256-v2` теперь пересобран прямо в своей папке из полноцветных
исходных JPG, а не из уже закодированного промежуточного WebP. Для каждого кропа
применяется anti-ringing Lanczos до 256 px, затем сохраняется прежний стиль
`quiet+flat+vign+fit+punch`, добавляются среднечастотные детали и выполняется один
финальный WebP q92. Это повышает читаемость тонких линий и фактуры; актуальный
набор `icons-256/` намеренно не затрагивается.

Воспроизводимая команда для временной папки:

```bash
PYTHONPATH=. .venv/bin/python tools/rebuild_v2_source_first.py \
  --out .cache/icons-256-v2-source-first --jobs 4
.venv/bin/python tools/verify_set.py .cache/icons-256-v2-source-first
```

После проверки временный кандидат можно синхронизировать в `icons-256-v2/`.

## Что дальше: аудит готового набора (`docs/quality-lab/`)

`quiet+vign` решил подложки (288 → 67 иконок с нечёрным фоном), но почти не тронул
разброс, который приехал из листов: экспозиция, контраст и насыщенность гуляют так,
что в сетке лута иконки читаются как разные рендеры. Новый `tools/audit_set.py`
мерит этот разброс и выдает списки конкретных выбросов
(`tools/build_set.sh audit`, ~30 с на набор).

Под них в `stylize.py` добавлены три пресета-правки — `fit` (автоуровни и
насыщенность к медианам набора), `flat` (добить подложку), `punch` (деталь на
64 px). Эти правки сохранены в текущем source-first кандидате. На новом полном
наборе контрольный аудит даёт: `dull-wash` 112 против 168, `dark` 24 против 38,
деталь на 64 px 9.69 против 9.05, а `clipped` 26 против 27; при этом
`verify_set.py` и `qa_icons.py` возвращают `problems: none`. Дополнительное
ослабление финального sharpen сделано специально, чтобы тонкие места не стали
«острыми». Подробное сравнение — **`docs/quality-lab/README.md`**.
`icons-256/` не тронут: `icons-256-v2/` остаётся кандидатом для просмотра и
отката.

## Грабли, о которые легко споткнуться

* **`tools/repack_icons.py --size 256` без `--out` теперь отказывается работать**:
  по умолчанию он пишет в `icons-256`, а это уже стилизованный набор. Скрипт
  скажет, что нужно `--out icons-256-base` (или `--force`, если действительно
  надо затереть стиль).
* **`tools/stylize.py --set` по умолчанию читает `icons-256-base`**, а не
  `icons-256`: иначе стиль накладывался бы на уже стилизованный набор.
* **Стиль необратим.** Δ 8.2 уровня — это ровно то, что видно на
  `docs/style-lab/quiet-vign-before-after.png`; вернуться можно только к базе.
* **Файлы весят больше блоков, чем кажется:** 39.1 МБ — это сумма байтов из
  манифеста, `du` покажет 48 МБ (блоки по 4 КБ на 4100 файлов).
* **Кодирование детерминировано** (сравнение `--jobs 1` и `--jobs 2` на 300
  иконках даёт одинаковые md5), поэтому набор воспроизводим из манифеста.
