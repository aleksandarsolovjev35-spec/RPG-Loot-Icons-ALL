# Лаборатория качества: что ещё можно улучшить в `icons-256/`

`docs/style-lab/` отвечает на вопрос «каким стилем нарисовать иконку». Здесь другой
вопрос: **почему 4100 готовых иконок в сетке лута всё ещё читаются как 4100 разных
картинок** и что с этим сделать. Всё ниже — замеры, а не вкусовщина: новый
инструмент `tools/audit_set.py` мерит каждую иконку по 14 признакам и смотрит не на
среднее, а на **разброс** по набору (в сетке иконка всегда соседствует с другими).

Короткий ответ:

| | сейчас | кандидат |
|---|---|---|
| разброс экспозиции (std) | 19.7 | **15.8** (−20 %) |
| разброс светов p95 (std) | 24.9 | **13.5** (−46 %) |
| разброс контраста (std) | 8.2 | **5.4** (−34 %) |
| разброс насыщенности (std) | 35.7 | **21.3** (−40 %) |
| иконок с нечёрной подложкой | 67 | **37** |
| иконок, мыльных на 64 px | 275 | **200** |
| иконок темнее/светлее нормы | 184 / 207 | **29 / 123** |
| вес набора | 39.1 МБ | **76.7 МБ** (lossless) |
| среднее изменение арта | — | 5.5 уровня из 255 |

Средние значения при этом почти не едут (экспозиция +0.9 %, контраст +2.8 %,
деталь на 64 px +3.1 %) — набор не «усредняется в серое», он **стягивается к своей
же середине**: крайние иконки приезжают к остальным, медианная не меняется.

### Текущий clean source-first merge в `icons-256-v2`

После лабораторного сравнения кандидат пересобран прямо из полноцветных JPG-кропов,
без усиления уже сжатого WebP. Финальный профиль стал консервативнее: denoise
`0.014`, steer `0.95`, sharpen `0.16`, Laplacian `0.28`, финальный sharpen `0.12`;
цепочка сохраняет `quiet+flat+vign+fit+punch`. Последний этап — **lossless WebP**,
поэтому к исходному clean-изображению не добавляется q92/q100-ошибка кодека.
Размер — 76.7 МБ, 4100 файлов 256×256.

Контрольный аудит финала: `bright-bg` 37, `dull-wash` 200, `dark` 29,
`bright` 123, `clipped` 27; std экспозиции 15.77, светов 13.53, контраста
5.42, насыщенности 21.28. `verify_set.py` и `qa_icons.py` → `problems: none`.
Сам набор `icons-256/` не менялся.

Таблицы ниже сохраняют подробности исторического q92 quality-lab сравнения;
для текущего clean merge воспроизводимая сборка и проверка описаны в
[`docs/PIPELINE.md`](../PIPELINE.md).

## Как мерили

```bash
.venv/bin/python tools/audit_set.py --set icons-256 --dupes          # сводка
.venv/bin/python tools/audit_set.py --set icons-256 --md docs/quality-lab/audit.md \
    --sheets docs/quality-lab --out .cache/outliers.json --rows .cache/rows_actual.csv
.venv/bin/python tools/audit_set.py --set icons-256-v2 --compare .cache/rows_actual.csv
```

4100 иконок, 2 процесса, ~30 с. Метрики (все по пикселям предмета, если не сказано
иное): `bg` — яркость рамки в 8 px (то, что нарисовано **за** предметом), `fill` —
какую долю кадра занимает предмет, `bbox`/`центр` — габарит и центр тяжести,
`touch` — доля рамки, занятая предметом (обрезка), `expo`/`p95` — экспозиция и
света, `contrast` — std яркости, `chroma` — насыщенность, `hf64`/`micro` — сколько
детали остаётся на 64 px (размер иконки в VTT) в абсолютных единицах и относительно
контраста самой иконки.

Пороги выбросов **фиксированные** (`LIMITS` в инструменте), а не «худшие 2 %»:
относительный порог всегда даёт одно и то же число иконок, каким бы хорошим ни стал
набор, иimprovement спрятать легко.

| подложка | 6.37 | 3.59 | **2.79** |
| экспозиция | 20.70 | 19.67 | **15.80** |
| света p95 | 23.73 | 24.89 | **13.62** |
| контраст | 8.61 | 8.23 | **5.41** |

| деталь 64 px | 2.78 | 2.43 | 2.18 |
| микроконтраст | 0.04 | 0.04 | 0.03 |

| метрика | база | `icons-256` | кандидат |
|---|---|---|---|

Главное: `quiet+vign` (нынешний стиль) сделал ровно то, что обещал — подложки
(288 → 67 иконок с нечёрным фоном) — но **совсем не тронул экспозицию, контраст и
насыщенность** (std 20.7 → 19.7, 8.6 → 8.2, 37.3 → 35.7). Их разброс пришёл из самих
листов: каждый лист рисовался отдельно, со своим светом и своей палитрой.

|---|---|---|---|---|

| `blank` | заполнение < 8 % | 1 | 1 | в кадре почти ничего нет |
| `dupes` | хеш ≤ 5/64 + Δ < 10/255, корреляция > 0.97 | 1 пара (2 файла) | — | один и тот же арт дважды |

## Что предложено: три пресета вместо одного стиля

Они не меняют технику рисунка, а правят несогласованность — поэтому идут **поверх**
`quiet+vign`, а не вместо него. Код: `tools/stylize.py`, пресеты `fit`, `flat`,
`punch`.

Замеры на выборке 600 иконок (вес — перекодирование в WebP q92):

| цепь | std экспо | std насыщ. | std контраста | деталь p05 | подложек | мыльных | КБ/иконку |
|---|---|---|---|---|---|---|---|
| база | 21.3 | 37.2 | 8.6 | 0.098 | 8.3 % | 0.2 % | — |
| `quiet+vign` (сейчас) | 20.1 | 35.6 | 8.0 | 0.082 | 3.0 % | 2.0 % | 9.44 |
| `+fit` | **16.2** | **20.8** | **5.2** | 0.083 | 3.0 % | 2.0 % | 9.44 |
| `+flat` | 19.9 | 35.3 | 8.1 | 0.081 | **1.5 %** | 2.8 % | 9.15 |
| `+punch` | 20.4 | 35.7 | 8.1 | **0.093** | 3.0 % | **0.8 %** | 9.85 |
| всё вместе | **16.1** | **20.8** | **5.2** | **0.091** | **1.8 %** | **1.0 %** | 9.65 |

* **`fit` — выравнивание по набору.** Per-icon автоуровни: чёрная и белая точки
  берутся из процентилей самого предмета (p2/p98), а целевые — из **медиан набора**
  (0.133 / 0.910), то есть медианная иконка не двигается вообще. Усиление
  ограничено (0.60…1.75×), насыщенность тянется к 0.174 отдельно, всё изменение
  затухает вне предмета, чтобы подложка осталась чёрной. Даёт −41 % к разбросу
  насыщенности и −34 % к разбросу контраста, вес не меняет.
* **`flat` — ровная подложка.** `quiet` работает с фиксированной силой, поэтому
  иконки с ярким свечением за предметом (до 84/255) остаются яркими. Здесь сила
  следует за измеренной подложкой: чёрную не трогает, яркую гасит почти до конца.
  Иконки, у которых предмет занимает всю рамку (`touch > 0.30`), пропускаются — там
  не подложка, а арт. −45 % выбросов, файлы на 3 % легче (плоский фон жмётся лучше).
* **`punch` — читаемость на 64 px.** Сначала замер: сколько детали от иконки
  остаётся в том размере, в каком её показывает VTT. Ниже цели 0.18 включается
  мягкий unsharp с порогом, сила пропорциональна отставанию; «мыльные» иконки
  (275 штук) получают подъём, чёткие не трогаются вовсе. Стоит +4 % веса.

## Демо точечной дорисовки контуров

Для `icons-256-v2` сделан отдельный безопасный пробник: шесть разных иконок
(тонкие линии, градиенты, фактура и крупные грани) обработаны без изменения
силуэта и композиции. Сравнение, карта изменений ×6 и отдельные PNG лежат в
[`256-v2-sharp-demo/`](256-v2-sharp-demo/); воспроизведение —
`tools/redraw_v2_demo.py`. Это демонстрация техники, а не замена всего
кандидатного набора.

## Что это стоит

| | цена |
|---|---|
| изменение арта (средняя \|Δ\| против `icons-256`) | 5.5 уровня из 255 (p99 26, макс 92) |
| для сравнения: перекодирование того же набора | 1.1 уровня (шум кодека) |
| для сравнения: `quiet+vign` против базы | 8.2 уровня |
| вес | 39.1 → 40.1 МБ (+2.6 %); `punch` добавляет детали, `flat` экономит |
| время | 2 мин 15 с на двух ядрах, воспроизводимо из базы |

Сила `fit` — ручка: `strength` 0.55 / 0.70 / 0.85 дают Δ 4.15 / 4.59 / 5.05 уровня.

**Кодек — отдельная и бесплатная по качеству экономия.** Тот же кандидат,
перекодированный с q92 на q88: 9.65 → 7.96 КБ/иконку (**−17.5 %**, весь набор ~33 МБ)
при росте ошибки кодека с 1.18 до 1.45 уровня — то есть втрое меньше, чем
собственное изменение от правок. q86 даёт −25 % веса при +0.43 уровня.

**Насыщенность — тоже ручка** (`fit(chroma=…)`): 0.174 (медиана, сейчас по
умолчанию) → средняя 72.6, std 21.0; 0.195 → средняя 76.1, std 22.0; 0.215 →
средняя 79.2, std 23.4. Нынешний набор: средняя 78.4, std 35.7. Если после правки
набор кажется суховатым, поднять цель до 0.195 — дешевле, чем откатывать всё.

## Чего делать не надо

* **Масштаб и центровка.** Заполнение кадра гуляет 0.07…0.82, но это семантика
  («монетка меньше меча»), а габарит предмета и так 0.95 кадра — выравнивать почти
  нечего, а цена — сломанный смысл размера. Разброс центра: ±0.05 кадра, править
  нечего.
* **`palette` / `pixel`** — уже проверено в `docs/style-lab/`: смена арт-дирекшена,
  `palette` к тому же +38 % к весу.
* **Альфа-вырезание** (убрать фон в прозрачность) — выглядит заманчиво, но за
  предметом не «фон», а нарисованное свечение: его вырезание даёт грязный контур, а
  VTT в большинстве тем всё равно подкладывает свою плашку.
* **128 px дериватив** — не улучшение, а удобство: вдвое легче, но решает только
  скорость загрузки в VTT. Делать, если нужно, отдельной папкой из `icons-256`.
* **37 обрезанных иконок** — это не пресет, а перекрой: `cut_icons.py` берёт
  соседний кадр. Отдельная задача, `audit_set.py --out` выдаёт список файлов.

## Повторы: 60 кандидатов, из них один настоящий

Первая версия детектора (только перцептивный хеш, расстояние ≤ 4 из 64) дала
16 групп и 60 файлов — и это была **ошибка**: в 4100 иконках сотни мечей, щитов и
зелий с одинаковым силуэтом. Число пар растёт примерно вдвое на каждую единицу
расстояния (2, 7, 13, 55, 162, 386… на d ≤ 1…6) — никакого «колена», за которое
можно зацепиться порогом.

Поэтому детектор двухступенчатый: хеш даёт кандидатов (d ≤ 5, ~160 пар), а
подтверждение — **по пикселям**: та же картинка, если средняя |разница| < 10 из
255 и корреляция 32×32 силуэтов > 0.97. Распределение Δ по 386 кандидатам
(бины 0-4-8-12-16-20-25-30-40-60-100):

```
0-4   4-8   8-12  12-16  16-20  20-25  25-30  30-40  40-60  60-100
  0     1      1      1      4     15     66    143    125      31
```

Одна пара в первом бине — и провал до следующего в 13.5. Это
`RPG Loot Icons 30/part2/icon_031` и `icon_036`: Δ 4.7, корреляция 0.998,
42 % пикселей совпадают полностью, отличия размазаны по кадру (1.7 % пикселей
differ больше 25), сдвиг не помогает (лучший dx=1 даёт 4.45 вместо 4.69) — то
есть это **тот же рисунок с правкой**, а не соседний кадр и не перекрас.

Всё остальное из прежних 60 — разные предметы одного типа: Δ 13.5…67 при
корреляции 0.63…0.93. Вывод скучный, но полезный: **повторов в наборе нет**,
чистить нечего, `icons-256` можно использовать как есть.

Листы: `dupes-pair.png` (обе иконки и карта различий ×4), `dupes-zoom.png`
(центр 120×120, ×2 без сглаживания).

## Как это испечь и как переключить

```bash
# 1. прикидка: 300 иконок, ничего не перезаписывая
.venv/bin/python tools/stylize.py --set icons-256-base --apply quiet+flat+vign+fit+punch \
    --out-dir /tmp/probe --limit 300

# 2. clean source-first кандидат (так собран текущий icons-256-v2/)
PYTHONPATH=. .venv/bin/python tools/rebuild_v2_source_first.py \
    --profile clean --lossless --out .cache/icons-256-v2-clean-lossless --jobs 4
.venv/bin/python tools/verify_set.py .cache/icons-256-v2-clean-lossless
.venv/bin/python tools/qa_icons.py .cache/icons-256-v2-clean-lossless webp

# Для исторического q92 A/B прогона поверх базы:
.venv/bin/python tools/stylize.py --set icons-256-base --apply quiet+flat+vign+fit+punch \
    --out-dir /tmp/icons-256-v2-q92 --role candidate --jobs 2

# 3. лист «до/после» между двумя готовыми наборами
.venv/bin/python tools/stylize.py --compare icons-256,icons-256-v2 \
    --out docs/quality-lab --compare-out docs/quality-lab/compare-actual-v2.png

# 4. сделать кандидат актуальным (база и icons-256-v2 не трогаются,
#    откат — перевыпечкой прежнего стиля в icons-256)
.venv/bin/python tools/stylize.py --set icons-256-base --apply quiet+flat+vign+fit+punch \
    --out-dir icons-256 --jobs 2
.venv/bin/python tools/build_set.sh verify
```

Порядок пресетов в цепочке важен: `quiet` → `flat` добивает подложку → `vign`
ставит одинаковую рамку → `fit` ровняет экспозицию и насыщенность → `punch`
возвращает деталь (после `fit`, иначе мерил бы чужую экспозицию).
